# 0002 — Hosting on GitHub Pages, deployed by GitHub Actions

- **Status:** Accepted
- **Date:** 2026-11-06

## Context

The club is a non-profit association with a near-zero budget. The site is fully static
(see 0001). The domain's DNS zone and mailboxes stay with the current hosting provider, and
e-mail must keep working through the migration.

## Decision

Host the built site on **GitHub Pages**. A GitHub Actions workflow builds the site and deploys
it as a Pages **artifact** (`upload-pages-artifact` + `deploy-pages`), so the built site is
never committed to the repository. The custom domain is verified in GitHub before DNS is
changed, to prevent domain takeover. Only the apex `A`/`AAAA` records and the `www` `CNAME`
point to GitHub; mail-related records are untouched.

## Alternatives considered

- **Cloudflare Workers static assets**: supports custom security headers, redirects and
  preview URLs. An apex custom domain would require moving the nameservers to Cloudflare and
  recreating the mail records, which puts e-mail at risk.
- **The existing shared hosting**: no CDN; the site would depend on a paid plan and share a
  server with the mailboxes.
- **Netlify / Vercel free tiers**: fine technically; Vercel's Hobby plan is limited to
  non-commercial personal use, and neither adds what this site needs over Pages.

## Consequences

- $0 hosting with a global CDN and free HTTPS for the apex domain and `www`.
- No custom HTTP headers: the CSP is set through a `<meta>` tag generated by Astro (hashed
  scripts, same-origin by default, `frame-ancestors` and HSTS are not possible this way).
- No official PR preview deployments; PRs are checked by CI and `astro preview` locally.
- Deployments take a few minutes after a CMS publish (see 0003).
